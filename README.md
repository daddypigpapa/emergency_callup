## 관리자(비개발자)를 위한 사용 설명서

이 시스템은 두 개의 화면으로 이루어져 있습니다.

- **관리자 화면** (`/a/`): 담당 공무원이 씁니다. 발령을 내고, 명단·지역을 등록하고, 현장 인력의 위치를 지도로 봅니다.
- **현장 화면** (`/f/`): 출동하는 직원이 자기 휴대폰으로 씁니다. 문자로 받은 링크를 눌러 들어갑니다.

이 안내는 **관리자 화면**을 처음 쓰는 담당자를 위한 것입니다. 컴퓨터 명령어(까만 화면에 글자 치는 것)는 전혀 필요 없고, 전부 마우스 클릭과 화면 입력으로 합니다.

### 0. 시작하기 전에 — IT담당자에게 받아야 할 것 3가지

시스템을 처음 설치하는 것은 기술적인 작업이라 IT담당자나 시스템 구축 업체가 해줘야 합니다. 담당자인 당신은 그 사람에게서 아래 3가지만 받으면 됩니다.

1. **관리자 화면 주소** (예: `https://mob.우리기관.go.kr/a/`) — 즐겨찾기에 등록해 두세요.
2. **내 관리자 아이디와 임시 비밀번호**
3. (있다면) 문자 발송 담당자 연락처 — 이 시스템은 문자를 "준비"만 해주고, 실제 발송은 기관에서 쓰던 문자 시스템으로 하거나, 문자 API가 연결되어 있으면 자동으로도 됩니다.

받으셨다면 이제부터는 전부 이 안내대로 마우스로만 하시면 됩니다.

### 1. 처음 로그인하고 비밀번호 바꾸기

1. 받은 주소로 접속 → 아이디·비밀번호 입력 → 로그인
2. 처음 받은 비밀번호는 임시 비밀번호이니, 로그인 후 눈에 띄는 곳(계정 관리 등)에서 바로 새 비밀번호로 바꿔 두세요.

### 2. 평소에 미리 준비해 둘 것 (비상 상황이 나기 전에)

오른쪽 위 **"설정"** 버튼을 누르면 준비 화면(`/a/setup.html`)이 열립니다. 위쪽에 탭이 5개 있습니다.

#### ① 명단 탭 — 우리 대원 명단 올리기

가장 먼저 할 일입니다. 대원 명단을 엑셀 파일로 만들어 올리면, 시스템이 자동으로 각 대원의 로그인 계정을 만들어 줍니다.

- 엑셀 첫 줄(맨 위 줄)은 반드시 아래 9개 항목을 **이 순서 그대로** 적어야 합니다.

  `소속 | 이름 | 행정전화 | 휴대전화 | 편성조 | 임무내용 | 임무지역 | 비고 | 로그인ID`

- 둘째 줄부터 대원 한 명당 한 줄씩 입력합니다. (임무내용·임무지역·비고는 비워둬도 됩니다. 편성조는 "3" 또는 "3조"처럼 적으면 됩니다.)
- 이 저장소의 [testdata/dummy_roster.xlsx](testdata/dummy_roster.xlsx) 파일을 열어보시면 예시 형식을 그대로 볼 수 있습니다. 이 파일을 복사해서 실제 명단으로 고쳐 쓰시면 가장 쉽습니다.
- 파일을 다 만들었으면 **[파일 선택]** → **[미리보기]** 버튼을 누릅니다. 신규/변경/오류가 있는 줄이 표에 나타나니, 오류가 있으면 엑셀에서 고친 뒤 다시 미리보기 하세요.
- 문제없으면 **[반영]** 버튼을 누릅니다. 그러면 새로 등록된 대원마다 **로그인ID와 임시 비밀번호**가 화면에 뜹니다 — **이 화면을 벗어나면 다시 볼 수 없으니** 캡처하거나 적어 두세요. 이 아이디/비밀번호를 대원 각자에게 알려주면(문자·구두 등) 대원이 나중에 현장 화면에 로그인할 수 있습니다.
- 대원이 그만두거나 부서를 옮기면, 명단 표에서 "비활성화" 버튼으로 계정을 바로 끌 수 있습니다.

#### ② 임무지역 탭 — 자주 쓰는 출동 장소 등록하기

교량, 하천, 주요 시설처럼 반복적으로 임무를 부여할 장소를 미리 등록해 두면 발령할 때 목록에서 고르기만 하면 됩니다.

- 이름, 위도, 경도, 반경(미터)을 입력하고 **[등록]**을 누릅니다.
- **위도·경도를 모르실 때**: 스마트폰이나 컴퓨터에서 지도 앱(네이버지도, 카카오맵, 구글지도 등)을 열어 해당 위치를 길게 누르면(또는 우클릭) 좌표가 표시되거나 복사할 수 있습니다. 그 숫자를 그대로 입력하시면 됩니다.
- 반경은 "이 범위 안에 들어오면 도착한 것으로 인정" 하는 원의 크기입니다. 너무 좁으면(50m 미만) 등록이 안 되고, 100m 이상을 권장합니다.
- ※ 현재 화면은 좌표를 숫자로 입력하는 방식입니다. 지도를 보면서 클릭으로 지역을 그리는 기능은 아직 없어서, 이 부분만 위와 같이 조금 수고가 필요합니다.

#### ③ 프리셋 탭 — 자주 쓰는 문구 미리 등록

발령종류(예: "비상 1단계"), 메시지, 임무 문구를 미리 등록해 두면, 실제 발령 낼 때 매번 새로 타이핑하지 않고 목록에서 골라 쓸 수 있습니다. 종류를 고르고 문구를 입력한 뒤 **[추가]**만 누르면 됩니다.

#### ④ 관리자 계정 탭 — 다른 담당자 추가하기

다른 직원도 관리자 화면을 쓰게 하려면 이 탭에서 아이디·이름·초기 비밀번호·역할(operator=발령·문자 담당 / admin=전체 관리)을 입력하고 **[추가]**하면 됩니다.

### 3. 실제 비상 상황이 발생했을 때 — 이 순서로 하세요

1. **[새 발령]** 버튼 클릭 (화면 위쪽, 발령이 없을 때만 보입니다)
2. 발령종류·메시지를 고르거나 입력
3. 화면이 조별로 임무·지역을 자동으로 채워줍니다(평소 등록해 둔 값 기준). 틀린 조가 있으면 그 자리에서 고치면 됩니다.
4. **[발령]** 버튼 클릭 → 대상 인원 전체에게 계정이 활성화됩니다.
5. 이어서 **[문자]** 버튼으로 문자를 준비합니다.
   - "수동"을 고르면 문구와 수신자 명단(CSV)이 만들어지니, 기관에서 쓰던 문자 발송 프로그램에 그대로 넣어 보내면 됩니다. 보낸 뒤 **[발송 완료 표시]**를 눌러주세요.
   - "문자 API"가 연결되어 있으면 그 자리에서 바로 자동 발송됩니다.
6. 이제부터 화면 아래 지도와 조별 칸에서 실시간으로 누가 출발했고, 이동 중이고, 도착했는지(초록색), 이탈했는지(빨간색)가 보입니다. 새로고침 할 필요 없이 자동으로 갱신됩니다.
7. 중간에 특정 조의 임무나 장소를 바꿔야 하면, 그 조 칸을 눌러 임무/지역을 고치고 **[변경 적용]**을 누르면 됩니다 — 그 조원들 휴대폰에 "임무변경확인" 알림이 자동으로 뜹니다.
8. 상황이 끝나면 **[상황종료]** 버튼을 누르고 "상황종료"라는 글자를 정확히 입력해 확인합니다. 그러면 모든 대원의 위치 수집이 자동으로 멈추고, 종료 문자가 나갑니다.
9. 상황이 끝난 뒤 누가 언제 응소했는지 표(CSV)로 받고 싶으면 관리자 화면에서 응소 기록을 내려받을 수 있습니다.

### 4. 자주 있는 질문

- **"직원이 로그인이 안 된대요"** → 설정 → 명단 탭에서 그 사람을 찾아 **[비밀번호 초기화]**를 누르면 새 임시 비밀번호가 나옵니다. 그걸 알려주세요.
- **"지도에 위치가 안 떠요"** → 대원이 아직 "위치 권한 허용"을 누르지 않았거나, 휴대폰 화면이 꺼져 있을 가능성이 큽니다. 화면을 켜두고 위치 권한을 허용해야 위치가 전송됩니다.
- **"지도 배경이 하얗게 나와요"** → 지도 타일(배경 그림) 서비스 키 설정 문제일 수 있습니다 — IT담당자에게 문의하세요. 지도가 안 보여도 임무·거리·"가는길" 버튼은 정상 작동합니다.
- **"실수로 다른 조 정보를 눌렀어요"** → 걱정하지 않으셔도 됩니다. 각 조는 서로의 기록에 영향을 주지 않게 설계되어 있습니다.
- **화면이 이상하거나 오류가 계속 뜬다** → IT담당자·개발팀에 어떤 화면에서 어떤 문구가 떴는지와 함께 연락하세요.

## 설치·배포 (IT담당자·개발자용)

여기부터는 시스템을 처음 설치하거나 서버를 운영하는 기술 담당자를 위한 내용입니다.

### 빠르게 시작하기

```bash
cp deploy/.env.example deploy/.env   # 값 채우기 (TILE_KEY 등)
export $(cat deploy/.env | xargs)    # 또는 서비스 매니저의 환경변수 기능 사용
go build -o bin/server ./cmd/server
./bin/server admin create --id admin --name "관리자" --role admin
./bin/server
```

또는 Docker:

```bash
cp deploy/.env.example deploy/.env
docker compose -f deploy/docker-compose.yml up -d
docker compose -f deploy/docker-compose.yml exec server /server admin create --id admin --name "관리자" --role admin
```

- 현장인력 화면: `/f/`
- 관리자 상황판: `/a/`
- 관리자 설정: `/a/setup.html`
- 헬스체크: `/healthz`

### 서비스 등록 (실행파일 직접 배포, SPEC §12.2)

**systemd** (`deploy/ecu.service`로 저장 후 `systemctl enable --now ecu`):

```ini
[Unit]
Description=Emergency Callup Location Tracking
After=network.target

[Service]
Type=simple
EnvironmentFile=/opt/ecu/.env
ExecStart=/opt/ecu/server
Restart=on-failure
RestartSec=3
User=ecu

[Install]
WantedBy=multi-user.target
```

**Windows (NSSM)**:

```
nssm install ECU "C:\ecu\server.exe"
nssm set ECU AppEnvironmentExtra BASE_URL=https://mob.example.go.kr DATA_DIR=C:\ecu\data ...
nssm set ECU AppDirectory C:\ecu
nssm start ECU
```

### 백업 복원 (SPEC §12.4)

백업은 `/data/backup/app-YYYYMMDD-HHMMSS.db`에 매일 03:00(Asia/Seoul)과
상황종료 직후 생성되며 최근 14개를 보관합니다. 복원하려면 서버를 멈추고
원하는 백업 파일을 `/data/app.db`로 복사한 뒤 다시 시작하세요.

```bash
systemctl stop ecu   # 또는 docker compose stop server
cp /data/backup/app-20260911-030000.db /data/app.db
systemctl start ecu
```

## 미해결/수동 확인이 필요한 항목

- **§10.1 지도 벤치마크**: VWorld 실키 발급과 카카오 SDK와의 실기기 비교
  측정은 아직 수행되지 않았습니다. 기본값은 Leaflet + VWorld입니다.
- **§10.3 가는길 실기기 확인**: 카카오·네이버 링크의 안드로이드/아이폰,
  앱 설치/미설치 4가지 경우는 실기기에서 수동으로 확인해야 합니다.
- **§16 미결 사항 1·2·3**: 사용자 확인 전까지 기본값(세션 24시간/종료+1시간,
  로그인ID는 관리자 지정, 문자는 manual)으로 구현했고 코드에
  `// DECISION:` 주석으로 표시했습니다.
- **`cmd/sim`의 500명·1시간 정식 실행(R16)**: 소규모로 동작을 확인했지만,
  전체 규모·시간의 실행과 판정 정확도 교차검증은 배포 전 별도로 수행하세요.
